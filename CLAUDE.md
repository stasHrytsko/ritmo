# Ritmo — контекст для Claude

Прочитай этот файл первым. Здесь что за продукт, как он устроен, что уже
решено и над чем работаем сейчас. Подробности — в `docs/`.

## Продукт

Ritmo — спокойный трекер дня: рутины, цели и заметки на одной ленте
времени. Интерфейс на русском, mobile-first PWA. Владелец — один человек,
делает продукт для себя и для рынка (русскоязычная аудитория в первую
очередь, потом остальной мир).

Главные отличия, которые нельзя размывать:
- **Лента дня** с линией «сейчас» — рутины выстроены по времени.
- **Медали вместо серий**: золото (100%), серебро (70–99%), бронза
  (50–69%). Пропуск не обнуляет прогресс. Позиционирование — «без чувства
  вины». Серия (streak) пока осталась в шапке Сегодня.
- **Карта**: одна закрытая карта с заданием «про жизнь, а не про
  продуктивность», раз в неделю или каждый день — выбирает пользователь.
  Сложность случайная и не показывается. После «Сделано» можно оставить
  заметку на память. Банк — 150 карт в `docs/weekly-cards.md`.
- **Заметки как бэклог**: запись → цель / задача / рутина.
- **Всё ядро бесплатно навсегда.** Платной может быть только косметика
  (см. `docs/monetization.md`).

## Стек и устройство

- React 19 + Vite + TypeScript, PWA (`vite-plugin-pwa`), IndexedDB через
  Dexie, Supabase (вход по почте кодом + облачная копия данных).
- Слои: `src/domain` (чистые правила: медали `award.ts`/`medal.ts`, карты
  `weeklyCards.ts`, бэкап, время) → `src/application/ritmoService.ts`
  (сценарии и view-модели) → `src/repositories/interfaces.ts` →
  `src/infrastructure` (Dexie, Supabase в `cloud.ts`). UI в `src/app`.
- **Синк**: снимок всех данных (формат бэкапа) в таблице
  `public.user_backups`, одна строка на пользователя, RLS, «последняя
  запись побеждает». Логика — `src/app/cloudSync.ts`.
- **Данные на устройстве принадлежат одному аккаунту**
  (`localStorage: ritmo.owner`). Другой аккаунт на устройстве → устройство
  очищается до входа. Выход → сначала синк, потом очистка.
- **Без аккаунта приложение не открывается** (экран входа). Новый аккаунт
  начинает с пустого листа + онбординг с шаблонами рутин.
- Схема IndexedDB v6 (`src/infrastructure/db.ts`). Любое новое поле
  данных: тип в `domain/types.ts`, миграция Dexie, `parseBackup` (старые
  бэкапы должны читаться), бэкап/очистка в `repositories.ts`, память в
  `testRepositories.ts`.
- Supabase-проект `ritmo`, id `escsqsbulidnfkatbpox` (eu-west-1). SQL
  миграции храним в `supabase/migrations/`.

## Команды

```bash
npm run dev      # локально
npm run check    # lint + типы + тесты — то же, что в CI; гонять перед каждым пушем
npm run build
npm run cards    # пересобрать банк карт из docs/weekly-cards.md
```

Визуальная проверка: Playwright с Chromium из `/opt/pw-browsers`
(`executablePath: '/opt/pw-browsers/chromium-1194/chrome-linux/chrome'`),
ширина 390 и 360, светлая и тёмная тема. Для входа без сети подменяем
сессию в `localStorage` (`sb-escsqsbulidnfkatbpox-auth-token`) и ответы
`**/rest/v1/user_backups**`.

## Как мы работаем

- Общение с владельцем по-русски, коротко и по-человечески.
- Работаем в рабочей ветке, **в `main` заливаем только по прямой просьбе**
  («залей в main»). Vercel собирает прод из `main`.
- После UI-правок — скриншоты и показать их владельцу.
- Не читать чужие данные в Supabase. Свои данные владельца — только по его
  просьбе. Почту владельца не публиковать в репозитории.
- Изменения в базе (миграции) — только с явного подтверждения владельца.
- Не открывать клавиатуру без касания поля: никаких `autoFocus`; шторка
  (`EditorSheet`) фокусирует себя, а не поле.
- Подтверждения — только через `askConfirm` (`src/app/components/confirm.ts`),
  не `window.confirm`. Ошибки Supabase — через `describeAuthError` (по-русски).
- Касания не меньше 44px. Цвета — только токены из `:root` в `styles.css`,
  тёмная тема обязана работать.

## Что сейчас в работе (октябрь 2026)

Цель — довести приложение и выпустить в **App Store и Google Play**.
Решения: обёртка **Capacitor** (не TWA), аккаунты разработчика будут
личными на владельца, у владельца есть Mac для сборки iOS.

Сделано: полировка по аудиту (`docs/product-audit-2026-10.md`, раздел
«Сделано»), онбординг, новая механика карт.

Осталось до сторов (подробно — раздел «Осталось» в аудите):
1. **Применить миграцию удаления аккаунта**
   `supabase/migrations/20261012_delete_my_account.sql` — ждёт «да» от
   владельца. Кнопка «Удалить аккаунт» в профиле уже есть и без функции в
   базе выдаёт ошибку.
2. **Почта для связи** в `public/privacy.html` (заглушка `CONTACT_EMAIL`) —
   ждёт ответа владельца.
3. **Capacitor** для iOS/Android + **локальные напоминания** (утро /
   вечер / каждое действие; выбор вернуть в профиль).
4. **Вход для проверяющего Apple** (тестовый аккаунт с постоянным кодом).
5. Материалы сторов: иконка 1024, скриншоты, описания, анкеты о данных.
6. Google Play: закрытый тест 12 тестеров × 14 дней (личный аккаунт).

После запуска: аналитика (первая рутина, D1/D7/D30), посадочная страница,
Telegram-бот с напоминаниями как канал роста, RuStore.
